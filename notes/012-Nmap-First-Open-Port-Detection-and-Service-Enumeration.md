Nmap - First Open Port Detection and Service Enumeration

Date: 2026-10-02

Goal

Understand how Nmap detects open ports and identifies services.

Environment

Kali Linux
Nmap 7.99
Python 3 HTTP Server

Procedure

1. Scanned localhost:

   nmap localhost

2. Result:

   All 1000 scanned TCP ports were closed.

3. Verified listening services:

   ss -tulpn

4. Result:

   No listening TCP or UDP services were running.

5. Started a temporary HTTP server:

   python3 -m http.server 8000

6. Verified listening port:

   ss -tulpn

7. Result:

   python3 was listening on:

   0.0.0.0:8000

8. Scanned the port:

   nmap -p 8000 localhost

9. Result:

   8000/tcp open http-alt

10. Performed service detection:

    nmap -sV -p 8000 localhost

11. Result:

    8000/tcp open http SimpleHTTPServer 0.6 (Python 3.13.12)

Observation

Before starting the Python server, Nmap detected no open ports.

After starting the server, Nmap detected port 8000 as open.

Service detection (-sV) identified the actual application running behind the port.

Python HTTP server logs showed multiple requests generated by Nmap during service detection.

Examples:

GET /
POST /sdk
GET /HNAP1
GET /nmaplowercheck...

This demonstrated that Nmap actively probes services instead of relying only on port numbers.

Key Concepts

Port
A network endpoint used by applications for communication.

Service
An application listening on a port.

Nmap
Discovers hosts, open ports, and services.

-sV
Attempts to identify the service and version running on an open port.

Result

Confirmed that Nmap can:

- Detect open ports.
- Detect network services.
- Identify service versions.
- Interact with applications during service detection.

Learned the difference between:

- A listening process (visible with ss).
- An open port (visible with Nmap).
- A network service identified through version detection.
